# 이대로 실험해도 될까?

중학교 과학 탐구 계획서를 **실험 전에 스스로 점검**하는 웹 도구입니다.
학생이 계획서를 쓰는 동안, 변인이 잴 수 있는 값인지 · 과정이 구체적인지 · 위험한 것은 없는지를 실시간으로 짚어 줍니다.

**답을 대신 써 주지 않습니다.** 모든 피드백은 학생이 스스로 고칠 수 있도록 질문 형태로 제시됩니다.

## 바로 쓰기

https://samsunk25-hue.github.io/science-inquiry-checker/

파일 하나짜리 정적 페이지입니다. `index.html`을 내려받아 더블클릭해도 똑같이 동작합니다.

## 설계 원칙

**AI를 쓰지 않습니다.** 규칙 기반 검사와 기기 안의 지식 표만으로 동작합니다.

- Gemini API 등 상용 LLM API는 약관상 18세 미만 대상 서비스에 사용할 수 없습니다
- 따라서 학생 동선에서 AI 호출을 완전히 배제했습니다
- 그 결과 API 키·서버·비용·대기열·연령 제한 문제가 모두 사라졌습니다

LLM·Vision AI로 하려던 일(교육과정 매핑, 안전 진단, 오차 예측, 장치 그림 검토)은 **기기 안의 지식 표와 규칙**으로 옮겨 담았습니다. 판정 근거가
파일 안에 그대로 보이므로 교사가 직접 고칠 수 있고, 같은 답안에 늘 같은 결과를 냅니다.
그림 인식만은 규칙으로 대신할 수 없어, **학생이 그림 속 기구를 눌러 표시하는 방식**으로
바꿨습니다(아래 ‘그림과 글 대조’).

**학생이 쓴 내용은 선생님의 구글 시트 말고는 어디로도 나가지 않습니다.** 웹폰트·이미지·분석 도구를 쓰지 않습니다. 외부 스크립트는 **PDF 파일을 만들 때만** 처음 한 번 cdnjs에서 받아 옵니다(html2canvas · jsPDF). 받은 뒤에는 기기에 남아 인터넷 없이도 쓸 수 있습니다. 학교 방화벽이 cdnjs를 막으면 PDF는 브라우저의 인쇄 창(‘PDF로 저장’)으로 대신 만들고, 나머지 기능은 모두 그대로 동작합니다.

**개인정보를 수집하지 않습니다.** 학번과 이름은 공용 기기에서 학생을 구분하고 제출 파일을 알아보기 위한 것으로, 그 기기의 localStorage에만 남습니다. 학생이 내려받는 보고서 머리와 파일 이름(예: `2103 김홍길 탐구1.pdf`)에만 들어가며, `계획서 + 점검 결과 저장`을 누를 때만 작성 내용과 함께 **선생님 계정의 구글 시트**로 제출됩니다(아래 ‘제출 모으기’).

## 점검 항목

2022 개정 교육과정의 탐구 요소를 여섯 갈래로 나누어 검사합니다.

| 갈래 | 예 |
|---|---|
| 가설 | 조건(`-면`/`-수록`)과 결과의 방향이 드러나는가, 조작·종속 변인이 문장에 포함되는가 |
| 변인 통제 | **재거나 정할 수 있는 값인가**, 조작 변인이 하나인가, 통제 변인이 충분한가, 변인끼리 겹치지 않는가 |
| 탐구 설계 | 번호 매긴 절차인가, 수치와 단위가 있는가, 측정 도구가 명시됐는가, 반복 측정과 대조군이 있는가 |
| 결과 예측 | 방향과 까닭이 있는가, 가설을 그대로 옮겨 적지 않았는가 |
| 앞뒤 맞추기 | 단계끼리 어긋난 곳 (아래) |
| 현실성·안전 | 위험 물질·화기·전기 등 8개 위험군, 물질별 안전 데이터, 섞으면 안 되는 조합, 주의 사항과 뒷정리 |

**변인 판정이 이 도구의 핵심입니다.** "식물의 건강", "잘 자란 정도"처럼 사람마다 다르게 보는 표현을 잡아내고, "운동하는 시간"과 "잠자는 시간"처럼 단위 낱말만 겹치는 경우를 서로 다른 변인으로 구별합니다.

## 앞뒤 맞추기 — 단계끼리 어긋난 곳

칸 하나만 보는 대신 **단계 사이의 선후 관계**를 봅니다. 어긋난 곳에는 `앞뒤 맞추기`
표가 붙고, 답이 아니라 **어느 쪽이 맞는지 되묻는 질문**이 나옵니다.

- 주제에서 궁금해한 것과 가설이 서로 다른 것을 말하는가
- **재는 값(종속 변인)을 고정하겠다**고 적지 않았는가
- 고정한다고 적은 조건이 실험 과정에 실제로 나오는가
- 과정에서 쓰는 기구가 준비물에도 있는가
- **조건을 다르게 하기 전에 이미 재고 있지는 않은가** (줄 번호로 짚어 줍니다)
- 가설과 예측이 서로 반대 방향을 말하고 있지 않은가
- 예측이 가설을 그대로 옮겨 적은 것은 아닌가
- 그림 속 장치와 준비물·과정의 글이 서로 맞는가

## 그림과 글 대조

실험 장치 그림·사진을 올리면, **그림 속에 있는 기구를 눌러 표시**할 수 있습니다.
표시한 것과 준비물·과정의 글을 대조해 한쪽에만 있는 것을 알려 줍니다.
글로 설명하기 어려운 학생도 그림으로 설계의 빠진 곳을 확인할 수 있습니다.

## 안전 데이터 카드

준비물과 실험 과정에서 학교에서 자주 쓰는 물질·기구 22가지를 찾아, **위험 요인 ·
필요한 보호구 · 다쳤을 때 · 끝난 뒤 처리**를 카드로 펼칩니다. 보호구는 눌러서 안전
계획 칸에 바로 넣을 수 있고, 넣지 않으면 점검표가 계속 짚습니다.

- **섞으면 안 되는 조합**을 따로 경고합니다 (락스+산 → 염소, 락스+암모니아 → 클로라민,
  산+금속 → 수소, 드라이아이스 밀폐 → 파열 등)
- 메탄올·액체질소·수은처럼 **학생이 다루면 안 되는 물질**은 위험으로 막습니다

실제 MSDS를 대신하지 않습니다. 표에 없는 물질은 지도교사가 직접 확인해야 하며,
카드마다 그 사실을 함께 띄웁니다.

## 오차 미리 보기

설계를 다 쓰면, **이대로 실험했을 때 값이 어긋날 곳**을 실험 전에 짚어 줍니다.

| 갈래 | 예 |
|---|---|
| 한쪽으로 치우침(계통 오차) | 온도계 담그는 깊이, 눈금을 보는 눈높이, 그릇 무게, 손으로 누르는 초시계, "다 녹았다"의 기준 |
| 통제 안 된 조건 | 씨앗 개체 차이, 화분에 닿는 빛, 연습 효과, 닳는 전지, 바닥 상태, 주변 소리·빛, 그날 날씨 |

대비책을 **실험 과정이나 통제 변인 칸에 적으면 목록에서 사라집니다.** 잘 써 둔
학생에게 같은 말을 반복하지 않습니다.

## 교육과정 이어 붙이기

주제·가설·변인에서 **2022 개정 과학과의 영역**을 찾고, 이 계획서로 확인할 수 있는
**탐구 기능**(문제 인식 · 가설 설정 · 변인 통제 · 탐구 설계·수행 · 추리·예상 · 안전 고려)과
**교과 역량**을 태그로 붙입니다. 디지털 도구로 측정·기록한 흔적이 있으면 디지털 소양도
함께 표시합니다.

**성취기준 번호는 자동으로 붙이지 않습니다.** 학년과 진도에 따라 달라지므로, 영역과
기능까지만 추천하고 번호는 교사가 교육과정 문서를 보고 확정합니다.

## 맥락 맞춤형 탐구 틀

주제 칸에서 막힌 학생을 위해, **우리 지역·전통 기술·생활 문제·내 몸·환경** 가운데
관심 있는 쪽과 수준(기초·보통·도전)을 고르면 탐구의 틀을 만들어 줍니다.

틀의 `[ ]` 자리는 **학생이 채워야 점검을 통과합니다.** 채우지 않으면 미작성으로 남아
도장이 찍히지 않습니다. 답을 대신 쓰지 않는다는 원칙을 그대로 지키기 위한 것입니다.

## 결과 내보내기

계획서 전문과 점검 결과를 하나의 파일로 저장합니다. `.pdf` · `.doc`(한글·워드) 가운데 고를 수 있고, 모두 인쇄 창 없이 **다운로드 폴더에 바로 저장**됩니다. 파일 이름은 `학번 이름 탐구번호`가 기본으로 채워지고, 저장할 때 바꿀 수 있습니다.

## 제출 모으기 (구글 시트 · 교사모드)

학생이 `계획서 + 점검 결과 저장`(자유탐구는 `제출하기`)을 누르면, 파일 저장과 함께
**학번 · 이름 · 탐구 · 점검 결과 · 보고서 전문**이 선생님의 구글 시트 ‘제출’ 탭에 한 줄씩 쌓입니다.
같은 주소에서 **`교사모드`** 버튼(또는 주소 끝에 `#teacher`)을 누르고 선생님 이메일·비밀번호로 로그인하면 **학번별로 묶어** 볼 수 있습니다.
제출을 펼치면 학생이 PDF로 저장할 때와 같은 모양의 보고서가 보이고, 그대로 인쇄·PDF 저장할 수 있습니다.

처음 한 번만 설정합니다.

1. 구글 드라이브에서 새 구글 시트를 만들고, `확장 프로그램 → Apps Script`를 엽니다.
2. [apps-script/Code.gs](apps-script/Code.gs) 내용을 통째로 붙여 넣고, 맨 위 `TEACHERS`에 선생님 이메일과 비밀번호를 적습니다(여러 명이면 한 줄씩).
3. `배포 → 새 배포 → 유형: 웹 앱`, **실행 계정: 나**, **액세스 권한: 모든 사용자**로 배포합니다(권한 승인 창이 뜨면 허용).
4. 받은 웹 앱 주소(`https://script.google.com/macros/s/…/exec`)를 [config.js](config.js)의 `submitUrl`에 넣고 배포합니다.

`submitUrl`이 비어 있으면 아무것도 보내지 않고 파일 저장만 합니다. 학번이 없으면 보내지 않습니다.
Code.gs를 고친 뒤에는 `배포 → 배포 관리 → 수정 → 새 버전`으로 다시 배포해야 반영됩니다(주소는 그대로).

웹 앱 주소를 아는 사람은 누구나 제출할 수 있으므로, 시트에서 이상한 줄은 지워 주세요.
목록 보기는 `TEACHERS`에 적은 이메일·비밀번호가 맞아야만 됩니다.

## 규칙 고치기

판정에 쓰는 표는 모두 `index.html` 안에 모여 있습니다. 수업에서 자주 나오는 표현을 여기에 추가하면 됩니다.

| 표 | 무엇을 담는가 |
|---|---|
| `DIM` | 값의 종류를 가리키는 말 (양·온도·시간…) |
| `VAGUE` | 사람마다 다르게 보는 말 (건강·상태·효과…) |
| `SAFETY` | 위험군 8가지와 되묻는 질문 |
| `CHEM` | 물질·기구별 안전 데이터 (위험 요인·보호구·응급·폐기) |
| `MIX_RISK` | 섞으면 안 되는 조합 |
| `ERROR_RULES` | 오차 원인과 대비책 판정(`on`으로 찾고 `guard`로 넘어감) |
| `APPARATUS` | 그림·글에서 찾을 실험 기구 이름 |
| `CUR_AREAS` `CUR_SKILLS` `CUR_COMPETENCE` | 교육과정 영역·탐구 기능·교과 역량 |
| `CONTEXT_BANK` | 맥락별 탐구 틀 씨앗 |

`CHEM`에 물질을 더할 때는 `gear` 문장을 **마침표로 끝내야** 안전 계획 칸의 줄과 맞습니다.
`terms`에는 `'알코올(?!램프)'`처럼 정규식을 쓸 수 있습니다. 테스트가 이 두 가지를 확인합니다.

고친 뒤에는 반드시 테스트를 돌려 주세요.

```
node _test-rules.js
```

`index.html`에서 정규식을 직접 읽어와 실제 학생 답안 예시로 검사합니다. 규칙을 고쳐도 이미 해결한 오탐이 되살아나지 않도록 막아 줍니다.

## 한계

규칙 기반이라 **형식만 봅니다.** "물을 많이 줄수록 잘 자란다"가 과학적으로 타당한지는 판단하지 못합니다.
안전 점검도 어휘 목록에 없는 표현은 놓칠 수 있습니다. **지도교사의 확인을 대체하지 않으며, 보조하는 도구입니다.**

덧붙여 새로 들어간 기능의 한계는 이렇습니다.

- **안전 데이터**는 표에 있는 22가지만 찾습니다. 실제 MSDS가 아니며, 표에 없는 물질은 아무 말도 하지 않습니다
- **오차 미리 보기**는 낱말로 짐작합니다. 대비책을 다른 말로 적으면 이미 대비한 것을 또 짚을 수 있습니다
- **그림 검토는 그림을 읽지 않습니다.** 학생이 눌러 표시한 것과 글을 대조할 뿐입니다
- **교육과정 매핑**은 영역·기능까지만 추천합니다. 성취기준 번호는 교사가 확정해야 합니다
